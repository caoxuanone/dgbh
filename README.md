# 广电保活 · 随机页面访问器

每隔 N 秒（默认 30 秒）随机访问一个广电（10099）的地址，让网络一直有真实流量。

两个形态，代码共用同一份页面：

| | 桌面版 | 安卓版 |
| --- | --- | --- |
| 入口 | `start.bat` / `index.html` | `android/`（APK） |
| 循环在哪跑 | 浏览器页面 | 前台服务（原生 HTTP） |
| 切到别的 App | 继续跑 | 继续跑 |
| 锁屏 | 继续跑 | **暂停**，亮屏自动继续 |
| 流量统计 | 需要 `server.js` | 原生统计，天然准确 |

---

## 安卓版

### 运行机制

- 访问循环跑在 `TrafficService`（前台服务）里，用 `HttpURLConnection` 直接发请求，所以你把 App 切到后台、去用别的 App，它照样在跑。
- 注册了 `ACTION_SCREEN_OFF / ACTION_SCREEN_ON`：**锁屏立即暂停，亮屏 1 秒后自动继续**。
- 状态栏常驻通知（安卓强制要求），显示「已访问 N 次 · X MB」，带一个「停止」按钮。
- 页面 `index.html` 只是仪表盘：每秒向原生要一次快照，显示次数、流量、日志。App 切到后台时这个轮询会自动停掉。
- 每轮可以连发多个请求（默认 2 个）：一次唤醒干更多活，比「多唤醒几次」省电。
- 屏幕亮着时才跑，所以不需要 WakeLock，也不用常亮屏幕。

### 打包（GitHub Actions，不装 Android Studio）

仓库里已经放好 `.github/workflows/android.yml`。把这个目录推到 GitHub 就会自动编译：

```bash
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

然后：

1. 打开仓库的 **Actions** → 左侧 **build-apk** → 点最近一次运行。
2. 等 3~5 分钟，页面底部 **Artifacts** 下载 `gdxs-keepalive-apk`。
3. 解压得到 `app-debug.apk`（debug 签名，能直接装）。
4. 传到手机安装，首次要允许「安装未知来源应用」。

也可以手动触发：Actions → build-apk → **Run workflow**。

> 想用 Android Studio：直接打开 `android/` 目录，Gradle 同步完点 Build → Build APK(s)。需要 JDK 17。

### 装好后怎么用

1. 打开 App，点「开始」。第一次会问通知权限、以及「忽略电池优化」，都同意。
2. 通知栏出现「广电保活 · 后台运行中」，就可以切走去干别的了。
3. 想停：点通知里的「停止」，或回 App 点「暂停」。

### 保活设置（这一步很关键）

前台服务能大幅降低被杀概率，但国产 ROM 还会额外限制。建议一次性设置：

- **小米**：设置 → 应用设置 → 广电保活 → 省电策略「无限制」；自启动打开；最近任务里下拉卡片点锁头。
- **华为/荣耀**：应用启动管理 → 手动管理 → 允许自启动、允许关联启动、允许后台活动。
- **OPPO/vivo/一加**：电池 → 应用耗电管理 → 允许后台运行；自启动打开。
- **原生/类原生**：设置 → 电池 → 电池优化 → 找到本 App → 不优化（App 里点「后台保活设置」会直接跳转）。

### 流量大概多少

默认 17 个目标里有 11 个页面（服务端拿到的是 WAF 挑战页，约 23KB）和 6 个静态资源（合计约 1.35MB，其中 `common-85ed7.js` 一个就 565KB），平均**每个请求约 90KB**。

按「每轮请求数 × 间隔」算：默认每轮 1 个、60 秒 ≈ 5.4MB/小时；每轮 2 个、60 秒 ≈ 11MB/小时；每轮 2 个、30 秒 ≈ 22MB/小时。

想加量：调大「每轮请求数」，或往「目标网址」里加更多大文件地址（图片、JS、CSS 都行）。

### 省电

耗电的大头是**射频唤醒**，不是流量。每发一次请求都要把蜂窝/Wi-Fi 无线电叫醒，之后还有 5~10 秒的「尾时长」在耗电，这跟响应大小基本无关。

所以只有两件事真正有用：

| 做法 | 效果 |
| --- | --- |
| 间隔调长 | 唤醒次数直接减少，**最有效** |
| 每轮请求数调大 | 唤醒次数不变、流量翻倍 |

默认就是 **60 秒 × 1 个**。想在不缩短间隔的前提下加流量，把「每轮请求数」调到 2~3：唤醒次数不变，只多花一点传输时间。

已经内置的省电措施：

- **锁屏立刻停**：不产生任何请求和唤醒（这是最大的一笔）。
- **App 切到后台时，仪表盘停止每秒刷新**：只在页面可见时轮询服务状态。
- **不用 WakeLock**：不常亮屏幕、不阻止 CPU 休眠。
- 用原生 `HttpURLConnection` 不加载 WebView，省掉渲染开销。

大致参考（屏幕亮着、蜂窝网络）：30 秒一轮约 1.5%/小时，60 秒一轮约 0.8%/小时，锁屏为 0。Wi-Fi 下比蜂窝更省。

### 已知限制

- 安卓版是纯 HTTP，不跑 WebView 渲染。目标站 `www.10099.com.cn` 前面有阿里云 WAF，服务端只能拿到挑战页（日志里标「WAF挑战」，那 23KB 也是真流量）。真实整页渲染需要 WebView，而在后台不可靠，所以没做。
- 锁屏暂停是设计要求；锁屏期间不产生流量。
- 部分 ROM 在极端省电下仍可能杀掉服务，按上面的保活设置做一遍。
- 需要 Android 8.0 及以上。

## 桌面版

### 用法

**双击 `start.bat`**：起本机服务 `http://127.0.0.1:8787`，端口通了自动开浏览器。

- 服务跑在最小化窗口里，标题 **gdxs-server (close this to stop)**，关掉即停。
- 重复双击不会起第二个服务，只会再开一个页面。
- 没有 Node 时会退回直连模式打开 `index.html`。

也可以直接双击 `index.html`：不用装任何东西，但没有流量统计（跨域站点不允许 JS 读响应大小）。

命令行 / 换白名单：

```bash
node server.js
set ALLOW_SUFFIX=10099.com.cn,example.com && node server.js
```

### 桌面版怎么发流量

点「开始」会开一个独立访问窗口（460×880），每轮把随机页面导航进去，真实加载整页（HTML/JS/CSS/图片），实测一次首页约 0.9~1.2 MB。

> 为什么必须开窗口：目标站有阿里云 WAF 的 JS 挑战。服务端直接请求只能拿 23KB 挑战页；iframe 里因为第三方 Cookie 被拦会无限重载；只有顶层窗口能过。

### 界面

- 间隔默认 60 秒（最小 3 秒），支持 ±N 秒随机抖动；每轮可连发 1~6 个请求。
- 洗牌袋随机，一轮内不重复。
- 配置存 `localStorage`。
- 定时器在 Web Worker 里，抗后台节流。

### 目标清单

| 类型 | 地址 |
| --- | --- |
| 页面 | `/`、`/index.html`、`/login.html`、`/help-center.html`、`/browser-version.html`、`/transaction-manage-*.html`、`/personal-center-deposit-order.html`、`/help-center-video-ringtone.html` |
| 其他站点 | `cblink.10099.com.cn`（物联网平台）、`partner.10099.com.cn`（代理商门户） |
| 静态资源 | `/js/common-85ed7.js`、`/js/vendor-21074.js`、`/css/common-b2baa.css` 等 |

静态资源名带哈希，站点改版后会 404，把对应行删掉或换新名字即可。
